# Bundled adapter consumer experiment

This independent Gradle project resolves a versioned Knapshots runner and exercises generated KPaths in a real Android Studio through KEFS. It intentionally has no Knapshots checkout dependency and does not configure an adapter archive. `KNAPSHOTS_REPOSITORY` may select an unpublished local Maven repository; omit it for Maven Central. `-PknapshotsVersion=...` selects the release to test. The project also needs the KPaths artifacts and the KEFS-compatible compiler artifact prepared by KPaths' compatibility tooling.

`editor-driver.sh` can be selected as the driver for the existing `editorCompatibility` orchestrator. That orchestrator supplies each IDE and its KEFS archive; the driver prepares KPaths and runs this exact versioned consumer. Reuse the **same published JAR** for every IDE in a release matrix: rebuilding an adapter against each target would not test a fixed release. To assess a future IDE against a past release, point the consumer at that release without rebuilding it. The script currently requires a KPaths checkout for fixture preparation and a Gradle wrapper, but the consumer resolves Knapshots from Maven.

For the local packaging experiment, first build a compatible adapter once, then publish a release-shaped artifact into the local consumer repository with `-Pknapshots.releaseAdapterArchive=/path/to/adapter.zip -PVERSION_NAME=0.1.0`. This opt-in publication path is experimental: Gradle module metadata is disabled for the runner publication, and normal publication still produces an unbundled runner. Automating and enforcing the release build, validating adapter provenance, and broad IDE coverage remain future work.

The experimental `Bundled adapter compatibility` workflow builds one `0.1.0-ci` candidate against a selected baseline IDE, publishes it into a local Maven repository, and uploads that repository for every IDE matrix job. No candidate artifacts are published externally. Its default selectors cover the latest three stable Android Studio families identified on November 21, 2026. The prebuilt adapter's IDE compatibility still has to be established by the results.
